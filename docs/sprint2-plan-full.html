Two methods, compared

The course asks us to justify our method. Running two and comparing them is the cleanest justification.

Method 1 · LLM

Gemini free tier (Google AI Studio)

Send the skill fields with a few examples. Ask for a JSON list of atomic skills.

  • Finds skills phrased in any way
  • Recommended default in the course brief
  • Rate limits: needs caching and retry
  • Can invent skills that are not in the text
Method 2 · Embedding match

ESCO skill matcher (Zhang et al. 2022)

Embed each phrase and each of ESCO's ~14k skills. Keep matches above a similarity threshold.

  • Free, offline, no quota
  • Output already uses ESCO names, which helps Sprint 4
  • Misses skills that ESCO lacks
  • Threshold needs tuning

How we get a score

Posting #1042 Gold (us): SQL, Python, Tableau, statistical methods Extractor: SQL, Python, Excel ✓ SQL ✓ Python ✗ Excel (extra) – Tableau, statistical methods (missed)
Precision
2 / 3 = 67%

How much of what we extracted is right.

Recall
2 / 4 = 50%

How much of the true list we found.

F1
57%

One number that balances both. Average over all 100 postings.

Expect modest numbers. In the Myronenko 2024 paper, GPT-4 reached only about 46% F1 on skills with exact matching. We report both exact and partial (fuzzy) matches.

Papers we found

Method 2

Skill Extraction from Job Postings using Weak Supervision

Zhang, Jensen, van der Goot, Plank (2022). Uses ESCO skills plus embeddings to find skills without hand-labeled training data.

Scoring

Enhancing Skill Extraction Using Synthetic Data and Advanced LLMs

Myronenko, Pylieva (UCU, 2024). GPT-4 reached about 46% F1, and fine-tuned BERT about 52%. It sets realistic expectations, and it warns that exact-match scoring is strict.

Method 1

Comparative Analysis of LLMs in Structured Information Extraction from Job Postings

Springer, 2024. Compares commercial and open LLMs on extracting hard and soft skills. It supports comparing Gemini with a Groq model if we have time.

Ground rules

Cache every LLM call to disk. A re-run costs zero tokens.
No API keys in Git. Keep them in environment variables.
Log token counts. They go in the sprint report.
Public data only. No LinkedIn or Glassdoor.
