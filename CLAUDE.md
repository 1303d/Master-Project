## Key decisions (and why)
- **Dataset: Kaggle `arshkon/linkedin-job-postings`** (123,849 US postings, listed 2024-03-24 → 2024-04-20).
  Chosen by the team for recency/size. Its `job_skills` column has only 35 broad categories → useless as gold.
  ⚠️ It is LinkedIn-derived: the brief bans *scraping* LinkedIn but allows published datasets. **Approved** (user,
  2026-10-07; brief p.3/p.5 names Kaggle dumps). **Final corpus decision 2026-10-07: Kaggle**, not the teammate's
  Greenhouse pilot (`taxonomy-skill-project/`, 5 mostly-tech employers). Extractor = Gemini (brief p.7 free tier).
- **Rejected datasets:** `abigailhaddad/usajobs-scraping` (3.2M federal postings, 10.7 GB, many template/junk
  postings, federal-only) and `will4381/job-posting-classification` (skills column generated by GPT-4o-mini
  with admitted hallucinations; also LinkedIn-derived).
- **Tag, don't drop:** 16,320 duplicate descriptions, 7 missing, 636 short (<200 chars) are flagged
  (`is_duplicate`, `is_missing`, `is_short`, `is_usable`, `text_id`, `dup_count`). Embed/extract **unique** texts
  only; `dup_count` can weight skill frequency; duplicates map back for "supporting postings".
- **Gold set = 100 postings, labelled by humans** (brief requires hand labelling). 8 sectors + Mixed:
  IT 15, Health Care 15, Engineering 12, Sales+Marketing 12, Finance+Accounting 12, Management 10,
  Legal 8, Admin/HR/Customer Service 8, Mixed 8. Seed 42, 300–5000 chars, usable rows only.
  Sector = posting's **first-listed** LinkedIn job function.
- **LinkedIn function tags are noisy** (e.g. "Attorney" tagged IT; some postings have only one, wrong tag),
  so a `sector_fixed` column exists and scores should be reported by `sector_fixed`.
- **Labelling = LLM-suggested, human-corrected.** Claude suggests; the human decides. Both are saved
  (`suggested_skills`, `gold_skills`) so the report can quantify human edits. Report must say this.
  Gemini (not Claude) is the extractor being evaluated.
- **Gold set is per posting** (skills unique within a posting, repeats across postings expected). ESCO is a
  dictionary, not a gold set — it cannot measure recall.
- **Labelling rules** (`data/gold/LABELING_RULES.md`): one skill per item, posting wording, drop filler
  ("skills", "strong", "knowledge of"), no degrees / years / licenses / certifications / traits / tasks.
  Duties-section items are tasks (Section A) unless also stated as a requirement.
- **Skill vocabulary idea:** an open, growing alias sheet linked to ESCO (+ Lightcast) — *not* a fixed
  top-500 list (would bias recall and pre-empt Sprint 3–4). ESCO API test on 16 legal terms: ~7 good,
  4 no match, 5 **wrong** matches (e.g. depositions → "mineral deposits") → legal skills must be
  human-reviewed; ESCO is EU-centric and misses US legal procedures/tools.
