How the skill library links work

The maths behind "library skill", "lift", "p / q" and "strong vs weak", using real numbers from our HDBSCAN run (1,931 Kaggle postings). ← back to the topics page

Numbers on this page are from run v1 (before the alias clean-up). Current run v2 (2026-10-23): 11,093 skills, 374 topics, 22.1% noise, 2,447 weak, 196 library skills, 980 links (255 strong); "excel" + "microsoft excel" are now one skill (250 postings).

Why we need a library at all

Topics group skills that mean similar things (excel, google sheets, vlookup). But some skills are used everywhere: communication is in 603 postings across all 8 sectors. It does not belong to one domain topic. HDBSCAN often marks such skills as noise (attention to detail has no topic at all).
So we keep two separate ideas:
  1. Topic = which skills are similar in meaning (from the embeddings).
  2. Library + links = which generic skills show up together with which topics in real postings (from counting).
The library is only a label on a skill. The skill keeps its own id, so nothing is duplicated.

Steps: decide which skills are library skills (tab 2), then link each one to the topics it really goes with (tabs 3–6).

Is a skill spread across sectors?

Each posting has a sector (its first LinkedIn job function, grouped into 8). For a skill, we count its postings per sector. Entropy turns that into one number: 0 = all in one sector, 1 = perfectly even over all 8.

Do a skill and a topic appear together more than expected?

Pick a real pair. We count postings that mention the library skill, postings that mention any skill of the topic, and postings that have both.

Lift = observed ÷ expected. Expected = (skill postings × topic postings) ÷ all postings, i.e. how many shared postings you would get if the two had nothing to do with each other. Lift 1 = no link; lift 4 = four times more often than chance.

Could the overlap be luck? (hypergeometric test)

Think of the 1,931 postings as balls in a bag. The topic's postings are coloured. The skill's postings are a handful we draw. The hypergeometric distribution says how many coloured balls a random handful would contain.

Blue bars = what chance gives. Orange bar = what we saw. p = the chance of seeing this many or more by luck.

We ran 67,501 tests. Some small p-values are luck.

197 library skills × 388 topics (minus excluded ones) = 67,501 pairs. With the usual cut p < 0.05, about 3,375 pairs would pass by pure luck. Benjamini–Hochberg (BH) fixes this: it controls the false discovery rate.

How BH works (here with 12 example p-values, m = 12):
  1. Sort the p-values from small to large.
  2. Give each a rank i = 1, 2, 3 …
  3. Its q-value ≈ p × m ÷ i (made non-decreasing).
  4. Keep the ones with q < 0.05.

Strong or weak: three checks, all must pass

Strong link = ≥ 5 shared postings and lift ≥ 1.5 and q < 0.05. Otherwise weak. Weak links are kept (thin lines on the Skill map), but are not claimed as real.
