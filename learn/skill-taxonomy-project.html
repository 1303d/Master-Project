What are we building?

You read thousands of job postings. You pull out every skill they ask for. Then you group similar skills and arrange the groups into a tree.

That tree is a skill taxonomy.

Taxonomy = a hierarchy of categories. Example: Data skills → Programming → Python.

Sprint 2: Text Extraction (2 weeks)

Goal: turn each posting into a list of atomic skill statements.

Atomic = one skill per statement. "Python and SQL" becomes two rows: "Python", "SQL".

Click a step for details.

  1. Load the Hugging Face dataset into a database.
    Sprint 1 was skipped, so do this first. Use SQLite (one file, no server). Store id, source, raw text. Also load ESCO and Lightcast for later.
  2. Agree the schema with Section A.
    At minimum: postings and statements tables. Statements need a kind column = "skill" for you, "task" for them.
  3. Choose an extraction method and justify it.
    Options: rules (find the "Requirements" section), NLP (spaCy, SkillNer), or an LLM (Gemini free tier). A common choice: section parsing to find the requirements, then an LLM to split them into atomic skills.
  4. Add caching and rate-limit handling (if you use an LLM).
    Caching = save each LLM answer to disk. A re-run reads the file and costs nothing. Rate limit = the free tier allows only N calls per minute; wait and retry when you hit it.
  5. Hand-label 100 postings.
    A human writes the "correct" skill list for 100 postings. This is the gold set. Split the work across team members.
  6. Measure precision and recall against the gold set.
    See tab 5. These two numbers go in your extraction quality report.
